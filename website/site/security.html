Security

Found a problem? Tell us first.

Updated 17 November 2026

Report vulnerabilities privately through GitHub's private vulnerability reporting on the TriageKit repository (Security → Report a vulnerability). Please don't open a public issue. The reporting link goes live here and in /.well-known/security.txt when the repository is published.

Scope

  • The TriageKit app (portable and installed editions, including the background service).
  • The update service.
  • Release integrity: anything that would let someone ship a fake update or a forged rule pack.

How we handle reports

  • We confirm receipt within 3 working days.
  • We aim to fix confirmed issues within 90 days and will agree a disclosure date with you.
  • We credit you in the changelog if you want.

Safe harbour

Research done in good faith, on your own systems or test accounts, without accessing other people's data or disrupting the services, won't be pursued. Please don't run denial-of-service tests against the update service.

How releases are protected

  • Signed updates. Each release announcement is signed with a release key that never leaves Cloudflare's storage; it isn't in the code or on any PC. Publishing needs a fresh passkey touch, and adding or removing a passkey needs a touch of an existing one, so a stolen login session can't publish. The app checks that signature, only moves to newer versions, and checks the download's SHA-256 before replacing anything. Honest limit: someone able to deploy new code to our Cloudflare account could use the key, so that account is what we guard most, and moving release signing to an offline key is on our roadmap.
  • Signed updates and rule packs. Update announcements and rule packs carry signatures the app checks with keys compiled into it. Unsigned rules are ignored.
  • Read-only. The scanner never deletes, quarantines or changes files, so it can't be abused to damage a system.
  • Code signing in progress. Releases are built by GitHub Actions from tagged source; Authenticode signing through SignPath Foundation is being set up. Until then, compare the SHA-256 with the one published for the release.
